2026 年 11 月 7 日，Google 发布了 Agent Development Kit（ADK）Python 版 2.14.0。这一版本将执行环境、A2A（Agent-to-Agent）集成、评测与核心运行时模块从实验状态毕业为稳定 API，同时新增 Microsoft Teams 集成、多轮评测和语义工具参数匹配，并提升了长流程多轮任务的执行速度。

<!-- more -->

## 执行环境与 A2A 转正

执行环境方面，`BaseEnvironment`、`LocalEnvironment`、`EnvironmentToolset`、`DaytonaEnvironment` 和 `E2BEnvironment` 现已稳定。`BaseEnvironment.read_file_stream` 支持按块流式读取文件，`ReadFileTool` 在读取指定行范围时无需将整个文件载入内存；`AgentEngineEnvironment` 同样按块读写大文件，超过 570 秒的命令会在服务截止前报告超时。

A2A 集成同样从实验状态毕业。新增的 `adk generate_agent_card` 命令可从命令行生成 A2A Agent Card，用于描述 Agent 的名称、能力与接口地址，供其他 Agent 发现和调用。

此次一并转正的还有 26 个认证、环境、应用、命令行与缓存模块，以及 16 项工具集与集成功能，包括 Bigtable、Computer Use、Daytona 与 E2B 环境、环境仿真、GCS、MCP Agent Server、Pub/Sub 和 Spanner 等。转正后，这些功能无需再处理实验性警告，相关的功能开关也不再起作用。

## 评测

评测方面新增 `MultiRunConfig`，`adk eval` 支持 `--num_runs` 与 `--parallelism` 参数，可对每个评测用例多次并发运行，并汇总多轮的分数或通过率。`AgentEvaluator` 现可直接评估运行时构建的 `BaseNode` 或 `App`，`--eval_storage_uri` 允许把评测文件存放在只读 `agents_dir` 之外。

新增的 `ToolArgsMatcher` 用于在评测与环境仿真中比对工具调用参数，支持精确匹配、大小写不敏感匹配、数值容差匹配，以及基于大模型的语义匹配。

## 新集成

新版本新增 `TeamsRunner`，可将 ADK Agent 接入 Microsoft Teams 的聊天与频道；新增 `OpenAIDecisionsClassifier`，使用 OpenAI Decisions API 对工作流与工具调用的门控问题进行分类。`MongoDbMemoryService` 新增向量检索模式与 TTL 过期时间，用于 Agent 的记忆管理。

## 性能

长流程多轮任务的执行速度有所提升。发布说明中给出的数据是：一个 30 节点工作流的 200 轮运行提速 23%，峰值内存降低 9%。发布说明未公布测试的硬件基线，也未指明与哪个先前版本对比。

## 破坏性变更

`RunSkillScriptTool` 在环境模式下不再接受自由形式的 shell 命令字符串。配合 `SkillToolset` 环境使用时，模型改为传入结构化的 `args`、`short_options` 与 `positional_args`，脚本从技能目录经校验后的路径运行，且仅支持 `.py`、`.sh` 与 `.bash` 三种脚本类型。仍传入 `command` 的调用会返回 `INVALID_ARGUMENTS`。发布说明指出，这一改动堵住了提示注入的模型执行任意 shell 命令的漏洞。

另一项破坏性变更涉及枚举类型的工具参数：`FunctionTool` 中标注为 `Enum`、`Optional[Enum]` 或 `list[Enum]` 的参数，现在收到的是枚举成员而非模型发送的原始字符串。此前直接与字符串比较、按字符串键查字典或对参数调用字符串方法的代码需要改为与成员比较、使用 `.value`，或改用 `StrEnum`。
