OpenAI 于美国当地时间 **2026 年 9 月 29 日**在 DevDay 2026 发布 GPT-6.1 Sol。它是 GPT-6 Sol 的升级版，官方将重点放在 Agent 编码、计算机操作和多步骤工作任务上。对开发者而言，这次发布值得关注的还有更低的缓存输入价格。

## 发生了什么

GPT-6.1 Sol 已通过 OpenAI API 提供，模型标识为 `gpt-6.1-sol`；同时向符合条件的 ChatGPT Work 和 Codex 用户开放。官方说明它目前尚未在普通 Chat 界面提供。

API 标准价格按每 100 万 token 计算：输入 **2 美元**、输出 **10 美元**、缓存输入 **0.10 美元**。标准输入和输出价格与 GPT-6 Sol 相同，缓存输入价格则从 0.20 美元降至 0.10 美元。

在官方公布的测试中，GPT-6.1 Sol 在 DeepSWE v1.1 的复杂软件工程任务上接近 GPT-6 Astra，单任务成本约为后者的五分之一；相较 GPT-6 Sol，最高成绩提高了 **6.4 个百分点**。OpenAI 还称，在 OSWorld 2.0 离线集的最高推理档位，它比 GPT-6 Sol 高 **7 个百分点**。这些是厂商公布的评测结果，具体项目中的完成率与成本仍需自行验证。

## 对 Java / Agent 开发有什么影响

**我的判断是**，这款模型适合进入现有 Agent 流程的候选模型列表，尤其是需要反复调用工具、读写代码或处理长上下文的任务。但不宜只看 token 单价：一次任务的实际成本还包括工具调用、失败重试和更高推理档位带来的消耗。

如果正在用 Java 构建 Agent 或 RAG 应用，可以拿同一批真实任务分别测试当前模型与 `gpt-6.1-sol`，记录任务完成率、错误类型、响应时间、每任务总成本和缓存命中情况，再决定哪些步骤值得切换。对于重复使用系统指令、工具定义和知识上下文的流程，缓存输入降价尤其值得测算；最终节省多少，取决于实际命中量。
